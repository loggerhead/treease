# Treease 用户故事

## 说明

本文档只描述用户行为、用户目标和期望体验。它用于对齐：用户为什么使用 Treease、会怎样使用 Treease、每个能力对用户有什么价值。

## 产品概览

Treease 是面向结构化文本的 editor + Graph 工作台。用户可以把结构化内容导入 editor，在左侧查看和编辑文本，在右侧通过 Graph 理解结构，并在两者之间来回定位、编辑、比较和导出。

Treease 关注的是一条连续的使用体验：用户打开内容、理解结构、定位字段、编辑内容、确认变化、比较差异、导出结果。Graph 不是独立展示页，editor 也不是孤立文本框；二者共同服务于同一份内容。

## 目标用户

- 配置与数据文件维护者：需要打开、整理、转换并导出 JSON、YAML、TOML、CSV、Python dict、JavaScript object 等结构化文本。
- 前端 / 后端开发者：需要在 editor、Graph 和 Tree Path 之间快速定位复杂嵌套字段，并确认修改后的结构变化。
- 调试与测试人员：需要比较两份结构化内容、复制结构路径、定位差异并复现问题。
- 大文件分析用户：需要导入大型 JSON，并在等待过程中看到明确的处理进展。
- 命令行用户：需要在终端中处理结构化输入、控制输出格式或直接更新文件。

## 核心用户旅程

1. 导入本地文件，系统识别格式，左侧进入 editor，右侧生成 Graph 视图。
2. 移动光标到文本中的 JSON 块（JSONL 某行或日志嵌入的 JSON），Graph 自动提取并展示该块的结构。
3. 在 editor 中执行 format、minify、sort，或通过命令搜索快速触发文本操作。
4. 在 Graph 中搜索、点击节点、同步 Tree Path，并反向定位到编辑器文本范围。
5. 在 editor 中对值节点 hover，直接查看 URL、图片、颜色、日期、Base64、JWT、Unicode 等预览。
6. 在 Graph 中逐层打开子图工作区，沿着嵌套结构继续阅读、定位并编辑局部内容。
7. 在 Graph 中编辑值，系统将修改回写到 editor。在 editor 中编辑，会局部更新 Graph。
8. 导出为目标格式，先在右侧预览转换结果，再下载文件。
9. 加载第二份内容进入 Compare，优先按结构比较；无法按结构比较时，展示文本差异。
10. 打开 Settings，调整编辑器、格式化、视图和交互偏好，并保存到本地。
11. 在命令行中使用 `treease` 处理输入、查看输出或直接更新文件。

## 用户故事

### US-01 导入文件并自动识别格式

作为配置或数据文件维护者，我希望从本地选择或拖拽文件后自动识别格式并载入 editor，以便无需手动复制内容就能开始查看和编辑。

- 用户行为：选择或拖拽本地文件。
- 用户期望：Treease 自动识别内容格式，左侧显示原文，右侧展示可理解的结构视图。
- 用户价值：减少导入前的准备工作，让用户更快进入阅读和编辑状态。
- 期望体验：
  - 支持的文件能直接进入 editor。
  - 对可展示结构的内容，Graph 能反映当前文本内容。
  - 导入成功后用户能明确知道文件已经载入。

### US-02 在混杂文本中定位并查看 JSON 块

作为日志排查或数据调试用户，我希望在 editor 中移动光标到一行 JSONL 记录或日志中的 JSON 片段时，Graph 自动解析并展示该 JSON 块的结构，以便在混杂内容中快速理解当前行的数据结构。

- 用户行为：在 editor 中移动光标到文本中的某个 JSON 对象或数组上（如 JSONL 的一行、日志中嵌入的 JSON）。
- 用户期望：Treease 从光标位置提取出完整的 JSON 容器，在 Graph 中展示其结构。
- 用户价值：不需要手动从日志或混合文本中复制出 JSON 再粘贴解析，光标所在的 JSON 结构直接在 Graph 中可见。
- 期望体验：
  - 光标移到 JSONL 某行时，Graph 展示该行 JSON 的结构，其他行不在 Graph 中显示。
  - 光标移到日志文本中嵌入的 JSON 片段时，Graph 只展示 JSON 部分的结构。
  - 编辑器中选不到合法 JSON 容器时，Graph 保持之前的内容不变。
  - 光标离开当前 JSON 块后，Graph 内容被替换或清空。

### US-03 在 editor 中整理文本

作为结构化文本编辑用户，我希望在 editor 中快速执行 format、minify、sort，以便把内容整理成更适合阅读、传输或提交的形态。

- 用户行为：点击底栏操作，或通过命令搜索触发文本操作。
- 用户期望：当前文本立即更新为对应结果。
- 用户价值：不用离开当前页面，也不用复制到外部工具处理。
- 期望体验：
  - format 后内容更易阅读。
  - minify 后内容更紧凑。
  - sort 后字段顺序更稳定。
  - 操作入口容易发现，也能通过搜索快速调用。

### US-04 在 Graph 和 Tree Path 中定位字段

作为调试复杂嵌套结构的开发者，我希望在 Graph 中搜索或点击节点，或点击 Tree Path 路径片段，同步 editor 选区，以便快速找到字段在原文中的位置。

- 用户行为：在 Graph 中搜索、点击节点或查看选中节点；点击 Tree Path 路径片段跳转到对应位置；复制完整 Tree Path 路径用于沟通。
- 用户期望：Tree Path 展示当前位置，editor 自动定位到对应文本范围，graph 高亮对应单元格；点击路径片段时 editor 和 Graph 同步跳转。
- 用户价值：降低理解深层嵌套结构的成本，减少手动查找字段的时间，让问题定位和团队沟通更精确。
- 期望体验：
  - 点击 Graph 节点后能看到对应 Tree Path，且 editor 对应文本被选中。
  - 选中 Graph 搜索结果后 editor 和 Graph 同步跳转到对应节点。
  - 点击 Tree Path 中的父级路径片段，editor 和 Graph 同步跳转到对应节点。

### US-05 在 editor 中 hover 值节点查看预览

作为阅读数据的用户，我希望在 editor 中 hover 到值节点时直接看到图片、URL、日期、颜色、Base64、JWT、Unicode 等预览，以便减少跳转到外部工具的次数。

- 用户行为：把鼠标停在 editor 中的某个值上。
- 用户期望：如果该值有可解释内容，Treease 直接展示预览。
- 用户价值：用户能在原文上下文中理解值的含义。
- 期望体验：
  - URL、图片、颜色、日期等值能被直观识别。
  - 预览不打断当前编辑和阅读。
  - 不适合预览的值不强行展示干扰信息。

### US-06 在 Graph 中 click 打开局部工作区

作为阅读复杂 Graph 的用户，我希望点击特定 cell 后直接在底部打开局部工作区，以便沿着同一条路径持续阅读、定位和编辑，而不是依赖 hover 瞬时预览。

- 用户行为：在 Graph 中 click 某个 key、value、index 或 row。
- 用户期望：Treease 继续保持 reveal / editor 联动，并在底部展开一个持久 pane；object/array 用 graph pane 展示，scalar 用 Monaco content pane 展示。
- 用户价值：用户能保持全局结构视野，同时深入查看和编辑局部细节。
- 期望体验：
  - 点击后工作区立即出现，不需要额外按钮或 hover 停留。
  - key 点击打开对应 key-value pair，index/row 点击打开对应 row，value 点击打开对应 path。
  - content pane 不额外展示 key 输入框，而是直接展示 path 和 value editor。
  - content pane 的 value 编辑复用现有双向编辑链路，不引入第二套提交语义。
  - 当用户在 content pane 连续输入时，工作区不会把旧的外部值回灌回来打断当前输入。

### US-07 在 Graph 中逐层打开子图工作区

作为阅读深层嵌套结构的用户，我希望在主图中点击某个结构化单元格后，直接在底部打开一个持久的子图工作区，并且能在子图里继续打开下一层子图，以便沿着一条嵌套路径持续阅读和定位，而不用回到整张主图。

- 用户行为：在主图点击对象或数组值单元格，在打开的子图 pane 中继续点击下一层结构化单元格。
- 用户期望：底部工作区按当前点击路径逐层展开子图 pane；每个 pane 都保持和主图一致的图形阅读方式、拖动方式和默认缩放。
- 用户价值：用户可以把注意力集中在当前嵌套链路上，逐层深入复杂结构，而不必在主图上来回缩放和寻找局部区域。
- 期望体验：
  - 主图点击结构化单元格后，底部立即出现对应子图 pane。
  - 在子图 pane 中点击下一层结构化单元格时，右侧继续展开新的 pane，形成最多 3 列的工作区链路。
  - pane 标题能让用户知道当前看的路径，但不需要占用额外路径轨空间。
  - 每个 pane 使用和主图一致的 graph canvas 交互，默认大小不缩小，并支持同样的拖动、缩放和平移边界限制。
  - 用户在子图中定位到某个值时，editor 仍同步到对应位置，保持图文联动不断开。
  - 当用户在某个 pane 内连续编辑同一路径时，最终保存的是最新输入，而不是中途某次旧提交。

### US-08 在 Graph 和 editor 之间同步修改结果

作为可视化编辑用户，我希望直接在 Graph 中修改值并同步到 editor；作为文本编辑用户，我希望在 editor 中修改后 Graph 随之更新，以便两种编辑方式始终围绕同一份内容工作。

- 用户行为：在 Graph 中修改某个值，或在 editor 中修改文本。
- 用户期望：另一侧能反映刚刚的修改。
- 用户价值：用户可以选择更自然的编辑方式，而不用担心两侧内容不一致。
- 期望体验：
  - Graph 中修改值后，editor 文本同步变化。
  - editor 中局部修改后，Graph 反映新的结构。
  - 如果某次修改无法完成，用户能看到明确反馈。

### US-09 导出为目标格式

作为需要在不同系统之间迁移配置的用户，我希望把当前内容导出为目标格式，并在下载前预览结果，以便确认转换结果符合预期。

- 用户行为：选择目标格式，查看预览，下载文件。
- 用户期望：Treease 根据当前内容生成目标格式文本。
- 用户价值：用户能在一个工作流中完成查看、调整、转换和导出。
- 期望体验：
  - 预览能帮助用户确认结果。
  - 下载文件名和格式符合用户选择。
  - 如果无法转换，用户能得到明确反馈。

### US-10 比较两份内容

作为配置审查用户，我希望加载另一份内容进入 Compare，并优先看到结构化差异，以便忽略无关格式变化、聚焦真实内容差异。

- 用户行为：打开 Compare，加载或粘贴另一份内容，触发比较。
- 用户期望：Treease 告诉用户两份内容是否相同，以及差异在哪里。
- 用户价值：配置审查、变更确认和问题定位更高效。
- 期望体验：
  - 内容相同时，用户能得到明确的相等反馈。
  - 内容不同时，差异能被清晰标出。
  - 当结构化比较不适用时，仍能看到文本差异。

### US-11 调整个人使用偏好

作为高级用户，我希望打开 Settings，调整编辑器、格式化、视图和交互偏好，并保存到本地，以便 Treease 更符合我的使用习惯。

- 用户行为：打开 Settings，调整设置，保存或重置。
- 用户期望：配置变更能影响后续使用体验，并在下次打开时保留。
- 用户价值：高级用户可以按自己的工作流定制 Treease。
- 期望体验：
  - 设置内容容易查看和修改。
  - 无效设置会被明确提示。
  - 保存后刷新页面仍然生效。
  - 重置后恢复默认体验。

### US-12 处理大文件时看到进度

作为大文件分析用户，我希望导入大型 JSON 时看到 Graph 建图进度，以便确认 Treease 正在处理，而不是卡死。

- 用户行为：导入大型结构化文件并等待 Graph 展示。
- 用户期望：处理过程中有清晰进度反馈。
- 用户价值：降低等待焦虑，让用户知道是否需要继续等待。
- 期望体验：
  - Graph 分批渲染，处理过程中能逐步看到图上节点出现。
  - 大文件处理时能看到进度或状态变化。
  - 内容准备好后 Graph 正常展示。
  - 如果处理失败，用户能看到明确失败反馈。

### US-13 在命令行中处理结构化输入

作为命令行用户，我希望使用 `treease` 处理输入、控制输出格式或直接更新文件，以便把 Treease 接入脚本和日常终端工作流。

- 用户行为：在终端运行命令，传入文件或输入内容，查看输出或写回文件。
- 用户期望：命令行为清晰、结果可预测、错误可理解。
- 用户价值：用户可以在无需打开 Web 页面时完成批量处理和日常自动化任务。
- 期望体验：
  - 查看帮助时能理解可用命令。
  - 普通处理结果输出到终端。
  - 用户要求更新文件时，文件内容被更新。
  - 出错时能看到明确错误信息。

## 使用边界

- Treease 面向结构化文本，不是通用富文本编辑器。
- Graph 用于帮助理解和定位结构，不替代全部文本编辑场景。
- Graph 中的编辑更适合明确的值修改，不适合作为任意结构调整工具。
- Compare 优先服务结构化内容审查；当内容无法按结构理解时，用户仍应能看到文本层面的差异。
- Settings 面向熟悉 JSON 配置的高级用户，不是面向所有选项的表单向导。
- 命令行能力服务自动化和批处理，不等同于 Web 中的完整交互体验。

## 维护规则

- 新增用户可见能力时，先补充对应用户故事，再决定是否需要补充更详细的工作流文档。
- 用户故事只描述用户目标、用户行为、用户价值和期望体验。
- 如果某个内容不能从用户视角理解，就不放在本文档。
