# Treease 编码协作规范

## 适用范围
- 适用于仓库内所有手写代码与与其配套的文档、测试、生成流程。
- 详细的 Web 和 Core 规则分别下沉到 `FRONTEND.md`、`CORE.md` 与模块级 `AGENTS.md`。

## 目录边界
- `apps/web/` 只承载 UI、交互、Worker、前端状态与浏览器运行时逻辑。
- `packages/core/` 只承载解析、格式化、算子、评估、视图构建与 WASM 导出。
- 跨层通信必须通过 Worker 与 WASM 协议，不直接穿透到对方内部目录。
- 通用技术说明与规范优先落在 `docs/`，避免散落在临时文档中。

## 单一职责
- 每个模块、文件、函数只承担一个明确职责；职责以"它为调用方提供什么能力"来界定，不以"它内部做了几件事"来界定。
- 当一个模块需要为两类不同调用方提供能力时，拆分为两个模块，各自面向单一调用方。
- 当一个函数内部出现超过一个可独立验证的阶段性结果时，拆分为多个函数，由调用方按需组合。
- 新增代码时，先确认目标职责是否已有对应模块承载；若有，扩展该模块而非新建并行实现；若无，新建模块并在对应目录 `AGENTS.md` 或 `README.md` 声明职责。

## 修改优先级
- 先复用现有目录和模式，再新增结构。
- 同一语义或流程在两处及以上重复出现时，应优先抽象为共享实现，避免并行维护。
- 默认优先采用跨语言共享的主链路与能力抽象；仅在语法、编解码或运行时边界确有差异且无法消除时，才允许保留语言特异化实现，并将差异收敛在适配层。
- 无非必要不允许实现 fallback；确有必要时，必须先明确说明原因并征得同意后再继续。
- 先更新真实协议源，再生成对应绑定文件。
- 先补测试，再扩大实现范围。
- 先写局部文档入口，再扩展全局索引。
- Web 异步结果落地必须遵循 `FRONTEND.md` 的 `FreshnessScope` 约束，避免分散手写过期判断。

## 禁止补丁式处理
- 禁止通过启发式重试、多套解释、随机 fallback、静默降级、局部特例或“只为当前样例服务”的字面量分支去修补主链路缺口。
- 出现语义、协议、身份、状态、定位或诊断问题时，必须优先收敛到单一协议、单一数据模型、单一职责边界，而不是在调用侧继续叠加补丁。
- 禁止在 Web、Worker、CLI 或其他上层重复解释应由 Core 或共享协议统一定义的语义；跨层规则必须回收到协议源或主实现链路。
- 下列信号默认视为补丁式处理：多轮 probe 或 retry、随机 key 或隐式 identity fallback、把未知结构伪装成合法值、双端重复解释同一协议、只为当前测试样例新增的特判。
- 若因兼容性或迁移窗口必须暂时保留例外，必须同时满足：明确写出保留原因与退出条件、把分支收敛在单一适配层、补最近实现层测试、并同步记录到对应文档。

## 可读性规则
- 函数或过程型实现必须按语义划分逻辑块；初始化、前置校验、主流程、状态同步、收尾等不同职责之间必须保留空行，不得无分隔地连续堆叠。
- 复杂逻辑块前必须补充简短说明，解释该块的目标、约束、边界或为何这样实现；注释应说明意图，不得逐行复述显而易见的代码。
- 若一个逻辑块复杂到难以通过空行和简短注释解释清楚，应优先继续拆分结构、收敛职责，再考虑补充更多说明。
- 禁止空 `else`；生产代码禁止空 `catch`，必须显式记录日志、保留错误信息或向上返回；测试代码仅在明确用于探测/重试且不会吞掉最终失败信号时允许空 `catch`。

## 所有权与生命周期规则
- 优先用 Rust 的类型系统表达所有权：能借用就借用，只有在需要跨作用域、跨调用、跨线程或跨 FFI/WASM 边界保留数据时才转成 `String`、`Vec`、`HashMap` 等 owned 结构。
- `String`、`Vec`、`HashMap` 等 owned 容器跨函数返回、session、缓存或 FFI/WASM 边界传递时，必须由返回值或状态对象自己持有；禁止返回指向局部 buffer、临时值或锁保护数据的 `&str`、`&[u8]`、iterator 等借用视图。
- 写入 `StoredAnalysis`、`StreamSession`、WASM 输出 payload 或其他跨调用状态的数据，必须以 owned 结构落地；借用视图只允许在单个局部作用域内做读取、解码、格式化或序列化。
- 生命周期意图优先通过更小的作用域、清晰的类型边界和函数拆分表达，不依赖 `scratch_*`、`result_*` 之类命名前缀硬编码规则。
- 代码评审时必须能回答：这段数据由谁拥有、有效到什么时候、跨边界时是否发生了明确的 move / clone；如果回答不清楚，先缩小借用范围、调整 API，或改为 owned 数据。
- 涉及跨生命周期状态的路径，优先在最接近实现层的 Rust/Core 测试中做最小复现与回归覆盖，再向外扩展到 WASM、Worker 或 Web 集成验证。

## 文档规则
- 根目录 `AGENTS.md` 只保留导航与硬约束摘要，不堆细节。
- 详细说明优先写入 `ARCHITECTURE.md`、`docs/agent-entrypoints.md` 指向的主题文档，或模块级 `AGENTS.md`。
- 文档内容应可机械验证：目录存在、文件存在、命令可找到、职责与目录一致。
- 文档引用默认不写行号；能落到稳定 symbol 时，优先写文件路径与函数名、类型名或 struct 名。
- 测试证据默认写测试文件与用例名；若没有稳定 symbol，再退回到文件路径加职责短句，不使用易漂移的行号区间。
- 文档治理的基础校验统一通过仓库根目录 `scripts/check-docs.mjs` 执行。
- 新增索引、执行计划或技术债文档时，必须同步维护对应上层入口。

## 临时脚本规则
- 临时 Python / Node 脚本必须先创建文件再执行，不得使用 `python -c`、`node -e` 或 heredoc 直接内联执行。
- 临时脚本文件名必须包含 `.tmp.`，例如 `foo.tmp.py`、`bar.tmp.mjs`，便于识别、检索与清理。

## 禁止事项
- 禁止在 `apps/web/` 新增解析器、算子、评估器等核心计算逻辑。
- 禁止在 `packages/core/` 新增 Svelte、DOM 或浏览器交互代码。
- 禁止只在对话中声明规则而不落到仓库文档。
